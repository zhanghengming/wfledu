# W03架构与优化复核

依据[PRD](../requirements/prd.md)、[DDD上下文](../technical/ddd-contexts.md)、[W03工作包](../planning/w03-identity-foundation.md)、[实施设计](w03-control-plane.md)。本记录为开发者架构复核；用户／团队的独立评审另记，不能据此宣称已合入或生产发布。

## 领域与依赖

身份领域负责全局用户、密码凭据、平台资格及会话；集团／组织领域负责成员、组织树与学校映射；管理资格负责ORG／ROLE／USER实际主体求值；资源领域负责原生对象与安全归属。SDK只有新DTO、API和线程请求桥接契约，方向仍为SDK→核心实现，不依赖XPack私有实现。

密码派生在事务外；身份重新核对、元数据变更、CAS、集团修订及审计在短JPA事务内。组织内核继续独立可测，成员／平台／资源使用相同管理事务入口；没有把行权限、业务查询或嵌入策略塞进W03管理服务。原生资源和侧表同事务，无“先创建再后台补归属”的窗口。

## 本轮实际发现及已落地修正

| 问题与根因 | 已落实措施 | 验证证据与边界 |
| --- | --- | --- |
| 局部HTTP装配不含完整产品的旧认证层，整包正式登录被401拦截 | 社区公开WhitelistUtils只接受管理过滤器校验后的精确请求线程作用域，finally清理，无永久公开路径 | 请求桥接固定测试及真实整包15次身份流程；关闭管理模式保持社区兼容 |
| 旧MVC拦截器覆盖管理no-store | 局部响应包装保护安全头，覆盖set／add／reset；不改全局社区响应 | 下游覆盖回归与实际整包响应头检查 |
| HTTP测试关闭open-in-view，漏掉完整产品持久化上下文复用 | 管理资格使用Spring绑定的EntityManager和活动RESOURCE_LOCAL事务；审计检查相同工厂绑定；新HTTP夹具启用open-in-view | 第5步实际61次接口复测，后续资源HTTP亦验证复用；没有移除事务归属检查 |
| 固定配置工具和Spring读取位置不同 | 两处绑定同一私有application.yml，回执核对PID、参数和配置摘要 | 统一配置不能证明全部连接池大小，容量使用实际连接数核对 |
| 专用MySQL上限40，两个测试应用稳定占用37条连接，无法容纳并发测试 | 仅任务13306上限调为80，保留私有回滚配置；并发测试前要求至少12条余量 | 同一MySQL PID，无重启、不改既有服务；失败日志保留，全部用例复跑 |
| 驱动未稳定提供外键约束名，断言报失败 | 真实反向引用和SQLState23000／1216或1452断言，结构校验仍核对精确FK | 4.5迁移拒绝／重试测试；不捕获后写成成功 |
| 通用异常响应会带内部事务／SQL诊断 | 仅管理server范围，对持久化、数据访问和内部状态异常返回现有40001；业务DEException仍沿原机制 | 原生登记失败HTTP测试断言明确失败并核对全量回滚 |

因此之后每个安全功能必须同时覆盖“领域／事务”“真实Servlet装配”“完整产品旧过滤链”三层。最终门禁把固定W03测试方法、实际整包接口用例、两个进程的JAR／PID／开始时间，以及15表结构纳入同一回执；旧120项或原五表检查不能替代新流程。门禁回归包含旧报告、漏控制用例、旧PID和高数量但缺方法的拒绝测试。

## 未提升为W03成果的能力

W03控制面ACTIVE不证明集团业务源已安全绑定；W06仍须独立数据库、账号、连接与命名空间验证后开放。GROUP_READ_ALL只作用当前集团，普通业务VIEW待W04策略；W03不默认授权查询／导出／编辑／分享。真实角色授权页面、学校副本、缓存／异步任务数据范围、React宿主免登录仍由W04／W05／W07／W08接续。

审计成功变更与登录拒绝已持久化；全量访问拒绝审计、保留归档与生产审计账号分离仍待后续。不可变JPA映射不阻止数据库特权SQL。平台资格公共配置接口未开放，初始化及合成验收夹具不作为生产资格管理页面。

暂不增加分布式缓存、另一套ORM或复杂框架；当前实际事务和请求边界足以支撑单节点W03。后续在授权、查询、嵌入接口接入同一上下文和修订失效契约，新增路径先登记归属与负测试，再开放功能。

## 最终门禁补充复核

冻结4.4的会话夹具必须显式声明4.4结构及迁移计划；使用“最新版本”辅助方法导致4.5落地后11项结构错误。已修正夹具，不放宽历史校验。门禁升级到W03双进程后，浏览器输入仍要求W02旧环境名；已同步精确W03身份校验并要求有效控制PID。真实浏览器与故障注入仍是必需检查。

容量属于测试前置条件：实测两个稳定账号占用25＋12条连接，Hikari配置目标2不能描述为整个产品连接上限。专用MySQL上限80；门禁在五并发错误密码测试之前记录实际上限、连接数与余量。资格、事务、响应及数据隔离规则保持。最终状态登记在验收文档。

## 统一功能通过后的架构与优化复核

门禁`0ab9427c-be07-4950-b663-60f4c1f8a39a`通过后，再检查正式调用链：SDK请求→管理server→manage／组织内核→实际JPA事务，身份／成员／资格重新求值，不由名称、前端头或合成管理员Bean提供资格；审计及原生归属与业务元数据同事务，线程上下文finally清理。SDK无核心实现依赖，社区公共桥接精确到已验证请求，不永久放行路径；4.1—4.5历史冻结与当前目标分开，无XPack源码或资源复制。

本轮优化已落实：完整产品旧过滤链和MVC纳入真实HTTP；OSIV夹具复用实际持久化上下文；字段严格转换只影响新DTO；内部错误脱敏；历史夹具明确版本；容量前置检查；浏览器和远程工具统一环境契约；门禁同时绑定固定用例、两个PID、配置、JAR和HEAD，提交后再复验。最终182／140／35／22／14与浏览器8、故障3已实测，不以设计或编译替代。
