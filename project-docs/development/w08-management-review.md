# W08基础管理闭环：开发者架构复核

2026-10-09。关联[实施顺序](../planning/w05-w10-continuous.md)、[页面设计](../technical/w08-management-ui.md)、[测试规范](testing.md)。本记录是开发者复核，不能代替用户／团队的独立人工评审。功能完成以远程整包、接口及真实页面验收为准。

## 已核对的设计和调用关系

`ManagementNavigationApi → ManagementNavigationServer → ManagementNavigationService → ManagementTransactions／ManagementAuthority → JPA`。新增SDK只包含公开契约，不反向依赖核心，不涉及XPack实现。普通用户集团发现直接限定有效成员关系；平台发现检查有效专属资格，不能据此前端名单授予管理能力。

导航投影复用当前管理能力算法和事务归属检查，身份/会话短事务重新核验，集团加读锁并复核有效状态。无选中集团只返回本人的平台资格，不返回其他集团管理能力。导航结果用于展示，原管理接口仍在自己的事务中鉴权；页面菜单和缓存状态不成为授权依据。

管理请求的集团／会话版本预期必须成对、唯一、合法且匹配认证上下文；身份事实仍由服务端产生。认证后发生的并发切换由原事务内的会话核验拒绝。未携带新预期字段的既有客户端保持兼容。再次选择同一集团不改变当前JPA版本的行为保持原状；回归必须使用真实跨集团切换证明旧页面拒绝，不能为了适配错误测试改动既有语义。

独立`enterprise.html`复用既有Vue、Pinia、组件及Axios。社区入口继续执行原行为。管理入口跳过社区配置初始化、Token刷新和HMAC，并限制同源企业API；企业成功只接受code=0，旧社区特殊code=50002在此属于冲突失败。语言初始化仅使用已打包语言资源，避免管理入口访问被关闭的自定义语言接口。

管理进程仅从打包类路径读取受控HTML／静态文件，保持就绪门槛和旧业务接口关闭。禁止任意文件、编码路径逃逸、带查询静态入口和错误方法；配合no-store、nosniff及同源CSP。静态文件开放不意味着开放业务配置或数据出口。

## 复核产生的修正

| 问题 | 处理 | 必须补充的验证 |
| --- | --- | --- |
| 页面静态分支可能早于就绪检查 | 将静态分支放在就绪检查之后 | 真实HTTP就绪及静态边界用例 |
| 集团导航在等待锁时状态可能改变 | 加锁后重新核对集团状态；缺失记录拒绝 | 停用集团及会话拒绝 |
| 切换时旧页面重新挂载可能发起新请求 | 切换期间卸载路由内容；取消旧请求，按generation拒绝迟到结果，成功后才恢复页面 | 浏览器切换和迟到响应负例 |
| 单独角色管理员可能没有成员／组织列表能力 | 不越过其他接口权限；有列表能力使用已授权选择器，无该能力可按原契约提交已知对象ID并由服务端校验 | 独立管理能力允许／拒绝用例 |
| 同集团选择被错误当成版本变化 | 更正测试条件，跨集团后检查旧预期拒绝和新集团无管理资格拒绝 | 本轮定向HTTP重新执行 |
| 全仓差异检查包含用户已有行尾差异 | 保留原文件和原差异，本轮按明确变更路径执行检查 | 原25项输入摘要未变及本轮差异检查 |

## 构建输入门槛的修正

首次整包`4f5b47b9-aade-40a7-9cdf-f4898d908e0b`在SDK和前端通过后，被`SOURCE_CHANGED_DURING_BUILD`拦截，未形成可交付整包。构建证明`w08-generated-input-proof.json`逐项核对：唯一变化是`unplugin-vue-components`自动生成、未跟踪的`components.d.ts`，其余产品输入与原25项受保护修改未变。

原因是构建输入清单仅识别自动导入声明，没有同时覆盖组件声明生成器；前端新增页面首次触发声明更新后才暴露。修正`product-inputs.py`的明确生成文件名单，不能通配排除所有`.d.ts`。同时`build-safe.py`保存真实输入清单，并在各阶段及结束时输出变化路径与前后摘要；保留一致性拒绝，不把失败改写为成功。新增两项相反回归：自动生成组件声明变化不影响输入身份，手写接口声明变化必须改变身份。修正后按新清单重新整包，不复用失败报告。

## CSP修复后的整包及页面复测

后续整包`54636a35-3598-4d7a-8c18-29daa6d686e8`通过，257项Java测试实际全部通过；JAR和两进程绑定见[资源恢复结果](w08-resource-recovery.md)。页面复测`32b39e44-a40c-41da-849f-eeb71ee47072`已验证初始化、登录、重置密码、集团切换、组织/成员/角色保存、任职学校配对、并发冲突及跨集团拒绝等19项；最后会话失效用例失败，整体未通过。无资产、页面异常或script/connect CSP错误。

该复测还发现测试调度存在竞态：进入集团仅等待页头集团编号，未等路由及新页面请求完成；下一步可能仍点击旧页面刷新按钮，等待了错误接口。退出也可能早于上一页挂载请求完成，从而把退出导致的401归入下个正常步骤。修正为进入后同时等待预期路由、页面请求结束，退出前结束前一操作；保留401会话失效负例和所有API/网络错误拒绝，不放宽错误白名单。该测试修正不改变产品代码，需以新报告复测，不能把19项通过改写为整套通过。

继续复测`41bce2c0-c48c-4f2f-b01b-5239c2f111c6`发现累积数据跨分页后加载中操作竞态：列表请求未结束时，分页仍可改变页码，而`run`的忙碌保护跳过新请求，造成显示页码与数据不一致。集团、组织、成员、角色/任职共五处分页在busy期间禁用；定向lint `dac7e48b-8887-4b69-8c07-10932d4c6192`通过。真实浏览器新增`management.pagination-inflight`：阻塞一次真实后端响应、确认分页按钮禁用、再恢复结果；完整门禁必需集合增为21项，不能遗漏该用例。

根因是忙碌保护仅写在操作函数，未一致传到分页控件；测试又假定新集团都在末页，没有覆盖跨页边界。后续管理页面复用“请求状态约束所有会改变查询范围的控件”的约定，并在累计页面测试使用真实多页数据、等待实际业务就绪。不能用增加固定睡眠或删除网络错误检出来掩盖竞态。分页源码变化后重新整包，先前257项通过仅证明前一个包。
