# 测试与质量门禁

## 测试分层

| 层 | 目标 | 发布要求 |
| --- | --- | --- |
| 静态 | 文档、配置模板、格式和秘密扫描 | 每个 PR |
| 单元 | 权限规则、Ticket 验证、配额计算 | 改动对应规则时 |
| Repository/迁移集成 | MySQL 8 真实语义、事务、历史数据、重试 | 涉及持久化时 |
| API 集成 | 身份、资源所有权、错误码、审计 | 每个新接口 |
| 前端/SDK | 路由、租户切换、Origin、事件协议 | 涉及 UI/嵌入时 |
| 端到端 | 两租户、OIDC、看板查询和嵌入 | 版本发布前 |
| 性能/安全 | 查询并发、SSRF、注入、跨租户 | 试点前 |

## 双租户测试夹具

准备租户 A/B、各自用户、角色、数据源、同名数据集和看板、不同数据内容。对每个资源接口执行 A→B 和 B→A 的读、写、复制、搜索、统计、导出、分享及下载负向用例。重复运行异步和并发场景，检查缓存与线程池串租户。

权限矩阵至少覆盖平台管理员、租户管理员、分析师、查看者、无成员用户、停用用户、过期应用。行列权限同一份策略覆盖预览、图表、下钻、导出、嵌入和 API。

## 现有构建约束

`core/core-backend/pom.xml` 的 Surefire 配置为 `<skip>true</skip>`，需要在测试框架落地时调整或建立独立测试模块并核对报告。当前 `core/core-frontend/package.json` 没有统一 `test` 脚本。任何 CI 成功都要检查真实测试数量；零测试不能标记为通过。`npm run lint` 会自动修复文件，只使用定向不带 `--fix` 的检查。

Phase 0 先提供静态检查入口 `node tools/phase0-check.mjs`。功能测试夹具、后端测试运行器和 E2E 脚本随第一个 POC 引入，不能在尚无功能实现时伪造通过报告。
