# 测试与质量门禁

## 测试分层

| 层 | 目标 | 发布要求 |
| --- | --- | --- |
| 静态 | 文档、配置模板、格式和秘密扫描 | 每个 PR |
| 单元 | 权限规则、Ticket 验证、配额计算 | 改动对应规则时 |

| 性能/安全 | 查询并发、SSRF、注入、跨租户 | 试点前 |

## 双租户测试夹具

准备租户 A/B、各自用户、角色、数据源、同名数据集和看板、不同数据内容。对每个资源接口执行 A→B 和 B→A 的读、写、复制、搜索、统计、导出、分享及下载负向用例。重复运行异步和并发场景，检查缓存与线程池串租户。

权限矩阵至少覆盖平台管理员、租户管理员、分析师、查看者、无成员用户、停用用户、过期应用。行列权限同一份策略覆盖预览、图表、下钻、导出、嵌入和 API。

## 校验属性与近似偏差回归

2026-10-08按[ADR-015](../adr/015-schema-validation-and-startup.md)补充：设计必须列出每个安全契约的比较属性、允许等价形式及拒绝用例，不以“全量校验”或用例总数替代覆盖表。先验证偏差夹具成立，再检查业务拒绝，并核对无自动修复。新增默认值大小写、索引前缀、降序和额外函数字段进入真实MySQL回归；规范化只允许明确的展示差异，字符串不能统一lower/trim。

本轮最终必需报告提高为46项Java，新增7项回归并锁定8个命名用例（包括补强的既有CHECK单元测试）；[回执门禁](../../tools/phase1/login-test-context.py)同时检查这些实际XML用例名和回执记录，14项门禁测试覆盖“数量足够但缺必需用例”、旧39项回执及缺回归证据的拒绝。收尾复查增加CHECK字面量内容变异，第一轮45项不能作为最终门槛。真实测试结果在[整改记录](schema-validation-review.md)，不是本规范自身的通过声明。

后续版本/JPA/API按ADR-015补充迁移前后、阻塞及失败期间的真实请求；已有默认值/前缀用例不能证明其他字段属性或尚未开放企业入口全部通过。

## 现有构建约束

`core/core-backend/pom.xml` 的 Surefire 配置为 `<skip>true</skip>`，需要在测试框架落地时调整或建立独立测试模块并核对报告。当前 `core/core-frontend/package.json` 没有统一 `test` 脚本。任何 CI 成功都要检查真实测试数量；零测试不能标记为通过。`npm run lint` 会自动修复文件，只使用定向不带 `--fix` 的检查。

Phase 0 先提供静态检查入口 `node tools/phase0-check.mjs`。功能测试夹具、后端测试运行器和 E2E 脚本随第一个 POC 引入，不能在尚无功能实现时伪造通过报告。

## 登录漏测后的必过项

2026-10-07起，每次含产品或测试工具改动的完整包交付，在指定任务测试区执行[登录回归门禁](login-regression.md)：桌面和移动各覆盖冷启动、错误密码拒绝、真实表单登录及刷新；API错误、JS异常、遮罩阻塞、静态资源不匹配或缺少用例均失败。另用404、遮罩及移动提交阻塞的故障控制证明检测有效，不能只复验正常页面。

执行入口为`tools/phase1/verify-delivery.ps1`；真实单测报告、源码/工具/JAR/进程、实际页面资源及本轮runId一致，提交或运行包变化必须重新验证。合格回执有效期使用服务器时钟，推送前由任务检出的pre-push检查；具体作用范围、凭据保护及未接入远端CI的限制见上述主文档。纯文档变更仍只执行文档与差异检查；未实现的企业页面和业务A/V不标通过。

## 后续验证固定执行清单

2026-10-08用户要求后续测试依据已确认规范执行。本文件定义测试覆盖，[登录回归门禁](login-regression.md)定义当前执行入口和证据要求，[ADR-015](../adr/015-schema-validation-and-startup.md)定义精确校验和后续启动门槛；历史执行记录中的39/45/46项不替代现行60项最低要求。新增功能还需加入对应必需用例，不将现有数量当作全部业务覆盖。

1. 测试前在本轮W/T记录已读规范、功能范围、允许/拒绝/边界场景、受影响入口、必需用例与验收编号；未实现入口单列待验证。
2. Bug修复先用真实入口复现；新增回归在旧实现上命中目标失败，再验证修复通过。数据库用例先证明真实MySQL偏差存在，最后检查无意外结构或数据修改。
3. 按远程开发规范完成对应完整包构建和功能整合验证，再执行正式交付门禁；保留桌面/移动真实表单及故障控制。规范新增的企业入口、跨集团及撤权验证随实现纳入，不能用社区登录结果替代。
4. 核对本次报告中的实际执行、必需名称、失败/错误/跳过及源码/工具/产物/进程一致性；失败、缺项、过期或变更后的旧回执不得放行。
5. 保存命令、结果、runId、提交、产物摘要和未覆盖项；完成开发者架构复查，用户/团队独立评审另记。只有所需验证完成才标记该功能完成。
