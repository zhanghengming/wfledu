# 企业 API 规范

## 路由和版本

新增企业 API 使用 `/api/enterprise/v1/{domain}` 作为逻辑路由前缀。实际外部路径还受 DataEase `/de2api` 代理和 `server.servlet.context-path` 影响，须在构建运行后验证。现有社区 API 的 URL 与序列化格式不批量重命名。

## 请求与响应

- 使用现有统一响应、异常和错误码体系。请求 DTO 显式校验必填、范围和长度；敏感字段禁止进入响应和日志。
- 资源 ID 使用既有 Long/Snowflake 规则；浏览器传输必须避免超过 JS 安全整数的精度损失。新 DTO 明确 ID 序列化策略，不修改全局 Jackson 配置。
- 时间按 ISO 8601 传递，服务端内部 UTC。列表查询指定最大 page size；排序字段只允许白名单。
- 新增 API 同步维护 SDK、后端实现、前端封装、OpenAPI、权限动作和负向测试。

## 认证上下文

| 客户端 | 凭据 | 服务端解析 |
| --- | --- | --- |
| 管理端浏览器 | 短期会话/现有认证机制 | 用户、成员、当前租户 |
| 业务系统后端 | App 服务端凭据 | 允许的租户、资源和换票 Scope |
| 嵌入 iframe | 一次性 Ticket 换取的短期会话 | App、外部用户、租户、资源 |
| 集成服务 | API Key | 租户、服务账号和 Scope |

前端提交的 `tenant_id` 不直接作为鉴权事实。切换租户是专门的服务端操作，成功后发新会话/上下文并清理旧租户缓存。

## 失败与幂等

权限拒绝、租户不存在、资源不存在、配额超限、Ticket 已消费、票据过期分别使用稳定错误码。对资源查找类接口不泄漏其他租户资源是否存在。创建嵌入票据、批量导入、导出任务等写操作支持幂等键或服务端去重；重试不得重复创建和扣费。

## 兼容

新增字段遵循向后兼容原则，弃用先公告后删除；外部 SDK 消息带协议版本。API Key 与嵌入 App 可以吊销、轮换和设置过期。OpenAPI 只发布首期真正实现并验证的接口。
