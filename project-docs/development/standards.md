# 全局开发规范

本文件补充上游根目录 `AGENTS.md`，不替代其已有代码约束。每个功能按“需求/威胁场景 → 契约 → 迁移 → 实现 → 自动验证 → 人工评审 → 合并”推进。

日志、指标和审计字段统一遵循 [可观测性规范](observability.md)。

## 后端

- 遵循现有 `sdk API → server → manage → Repository/Provider` 依赖方向。Controller 只负责边界校验和编排，实体不直接作为外部响应。
- Java 21、Spring Boot 3、`jakarta.*`、JPA/QueryDSL；不引入平行 ORM。业务 ID 沿用 Long/Snowflake 约定，前端注意精度。
- 新资源写入必须由服务端注入 `tenant_id`；读取、更新、删除都校验资源所属租户。Native SQL、批量更新、后台任务需单独审查。
- 事务只包围元数据库短操作；外部查询、导出、网络调用不在长事务内。ThreadLocal 在 `finally` 清理。
- 复用项目的异常、响应、缓存、日志和国际化机制。错误不得转为成功或空数据。
- 修改 Repository `save` 前检查 `JpaUpdateNonNullAspect` 的非空合并行为，显式清空字段使用可控更新语句。

## 前端

- Vue 3 + TypeScript，复用现有 API Client、Pinia、动态路由和 `element-plus-secondary`。2 空格、单引号、无分号。
- 页面中只显示当前租户允许的能力；权限实际在服务端判定。切换租户时清空相关 Store、路由和缓存。
- API 模型补齐类型，Long ID 不随意转成 JS Number；新增文案进入现有国际化资源。
- 嵌入 SDK 与管理页面隔离，协议版本化；`postMessage` 只接受白名单 Origin。
- 改动共享图表组件同时检查主应用、panel、mobile 和 lib 入口。

## API

完整接口契约见 [企业 API 规范](api.md)。

- 与 DataEase 现有 API 保持兼容；新增企业接口统一使用 `/api/enterprise/v1` 前缀，最终路径须与现有网关 context path 一起验证。
- 新接口定义请求/响应 DTO、OpenAPI 文档、权限动作、错误码、幂等性与审计事件。分页和错误响应复用现有公共类型，不引入第二套包装。
- 租户上下文由服务端身份解析；浏览器传入租户 ID 只能请求切换。查询、导出、分享、嵌入都要求资源所有权验证。
- API Key 绑定租户、主体、Scope、到期时间；只存密钥哈希，创建时显示一次。敏感写操作支持幂等键。

## 数据库与迁移

表、列、索引和敏感数据约束见 [数据库设计规范](database.md)。

- 新租户表统一 `tenant_id BIGINT NOT NULL`，业务 ID 沿用 Long/Snowflake；表级主键、索引和唯一约束按租户设计。全局表例外需列入白名单。
- 时间统一存 UTC，接口使用 ISO 8601；显示时使用用户时区。审计记录不可被普通业务删除。
- 表和字段注明类型、长度、空值、默认值、敏感等级。数据源凭据加密；不在索引中存明文秘密。
- 所有结构与历史数据变更进入新增的版本化 `SqlBlock`，先备份，再执行，再核验；具体规范见 [迁移手册](migration.md)。

## Git 与评审

- 官方源码 `upstream` 只读；本项目基于正式发布标签建立自己的工作分支。上游 `AGENTS.md` 对向官方贡献的 PR 流程仍适用，本项目内部合并以自己的目标分支和评审规则为准。
- 一个变更单元包含代码、迁移、测试、文档；不得把私有子模块、密码、构建产物或无关格式化一起提交。
- 涉及 SDK/公共契约、租户边界、权限规则、迁移和对外协议的修改，必须更新对应 ADR 或架构文档并由另一位评审者检查拒绝路径。
- 提交消息使用 Conventional Commits；合并前核对 `git diff --check`、相关测试和核心补丁登记。

## 完成定义

功能可用、权限拒绝路径正确、双租户测试通过、迁移可重试、配置可追溯、审计可查、文档更新、回滚影响明确。未验证的环境和数据库要在交付说明中列出，不能用“编译成功”代替端到端通过。
