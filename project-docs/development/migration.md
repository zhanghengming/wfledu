# 数据库迁移规范

源码现状：`InitSqlListener` 在启动时收集 `SqlBlock` Bean，按版本组 1、2、3、4 执行（W03新增4），并把版本、成功状态写入 `de_standalone_version`。失败记录保持 `success=false`，下次启动会尝试重跑同一版本。`spring.flyway.enabled=false`，部分 Profile 使用 Hibernate `ddl-auto:update`。

首期采用现有 `SqlBlock`，不叠加 Flyway/Liquibase。组4注册4.1，由enterprise.foundation.enabled显式开关控制，默认关闭；见[基础迁移](foundation-migration.md)。生产迁移/恢复演练仍待授权和验证。

每个迁移必须包含：唯一版本号、表/字段变更、历史数据回填、前后置条件、失败重试处理、验证查询和回滚/恢复说明。禁止修改已经执行的版本；失败重试不得重复插入、重复删除或产生重复索引。

租户化采用“扩展 → 回填 → 校验 → 收紧”四步：先加可空字段和新索引；基于受控、已确认映射回填可判定资源；核验所有行、引用关系和计数；最后加非空约束及唯一约束。每一步在隔离数据库上以空库、存量库、失败重启三种场景验证。对不能判定归属的行暂停，不猜测租户。

生产执行前创建元数据库和文件存储一致性备份；应用版本与迁移版本绑定。若新结构无法向后兼容，先实施双读/双写或维护窗口；回滚须采用经过验证的备份恢复，不假设反向 SQL 安全。

2026-10-07修订：旧“建立默认租户”来自早期兼容迁移设想，已由PRD/ADR-014的权威归属约束替代，不猜测未知资源。4.1只建空基础表，企业JPA映射/旧资源回填另行实施，不用Hibernate自动建表替代。

2026-10-08补充[ADR-015](../adr/015-schema-validation-and-startup.md)：结构比较不得通过大小写归并或列名聚合丢失字符串/索引语义；变异回归见[整改记录](schema-validation-review.md)。4.1 DDL冻结，本轮只修复校验，不新增迁移版本或自动ALTER。新增4.2之前分离历史DDL与当前目标验证，明确升级、部分失败及旧版本重试顺序；企业JPA自动DDL隔离及请求就绪控制必须先验证再开放对应入口。
