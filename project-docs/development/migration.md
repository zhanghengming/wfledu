# 数据库迁移规范

源码现状：`InitSqlListener` 在启动时收集 `SqlBlock` Bean，按版本组 1、2、3、4 执行（W03新增4），并把版本、成功状态写入 `de_standalone_version`。失败记录保持 `success=false`，下次启动会尝试重跑同一版本。`spring.flyway.enabled=false`，部分 Profile 使用 Hibernate `ddl-auto:update`。

首期采用现有 `SqlBlock`，不叠加 Flyway/Liquibase。组4注册4.1，由enterprise.foundation.enabled显式开关控制，默认关闭；见[基础迁移](foundation-migration.md)。生产迁移/恢复演练仍待授权和验证。

每个迁移必须包含：唯一版本号、表/字段变更、历史数据回填、前后置条件、失败重试处理、验证查询和回滚/恢复说明。禁止修改已经执行的版本；失败重试不得重复插入、重复删除或产生重复索引。

租户化采用“扩展 → 回填 → 校验 → 收紧”四步：先加可空字段和新索引；基于受控、已确认映射回填可判定资源；核验所有行、引用关系和计数；最后加非空约束及唯一约束。每一步在隔离数据库上以空库、存量库、失败重启三种场景验证。对不能判定归属的行暂停，不猜测租户。

生产执行前创建元数据库和文件存储一致性备份；应用版本与迁移版本绑定。若新结构无法向后兼容，先实施双读/双写或维护窗口；回滚须采用经过验证的备份恢复，不假设反向 SQL 安全。

2026-10-07修订：旧“建立默认租户”来自早期兼容迁移设想，已由PRD/ADR-014的权威归属约束替代，不猜测未知资源。4.1只建空基础表，企业JPA映射/旧资源回填另行实施，不用Hibernate自动建表替代。

2026-10-08补充[ADR-015](../adr/015-schema-validation-and-startup.md)：结构比较不得通过大小写归并或列名聚合丢失字符串/索引语义；变异回归见[整改记录](schema-validation-review.md)。4.1 DDL冻结，本轮只修复校验，不新增迁移版本或自动ALTER。新增4.2之前分离历史DDL与当前目标验证，明确升级、部分失败及旧版本重试顺序；企业JPA自动DDL隔离及请求就绪控制必须先验证再开放对应入口。

## 历史迁移与当前验证契约（落实ADR-015）

2026-10-08，[迁移演进](schema-version-evolution.md)已分离冻结FoundationSchemaV41和当前FoundationSchema目标；本节替代上文“分离待实施”，保留原决策理由。未来4.2必须新增SqlBlock、目标与字典，不能修改或删除历史4.1。当前生产仍只有4.1四表，测试4.2探针不是正式迁移。

组4仅接受连续无前导零4.1…4.N（单步数字1至999999999），启动前拒绝重复／缺步／非法计划、未知较新历史、缺失／倒退／重复成功／未解决失败跳步／空状态／非法rank；组40等不匹配。允许同一步失败记录后重试成功再前进。预检发生在监听器执行任一版本组前，不写新的失败记录；其他组比较契约不变。MySQL DDL可能部分提交，失败保留并幂等续跑；本契约没有自动降级、DROP或恢复。

当前验证器独立核验目标及完整de_ent_保留清单，未知表／视图或错误大小写拒绝，不自动修改结构或数据；SQL LIKE下划线必须作字面量转义。已成功旧迁移不能重跑或用于新版结构比对。每个正式版本仍须空库／存量／失败重试及生产备份恢复方案；请求就绪、多节点迁移独占与生产恢复未由本轮证明。

## 正式4.2审计迁移（替代此前待注册状态）

2026-10-08，新增冻结4.2 SqlBlock及五表当前目标，4.1冻结定义／指纹保持；此前合成4.2是上一单元测试探针，正式4.2是本轮的de_ent_audit_event，不混用。先只读核对V41，再核验或创建缺失审计表并后验；漂移拒绝，不自动ALTER、删表或补行。真实版本Repository／切面／监听器覆盖空库、保留旧行、重复启动、DDL提交后失败及保留失败账本再重试。

任务元库新增空表并记录4.2成功；旧4.1程序面对该较新历史拒绝启动，不能删账本降级。普通代码回退需兼容五表及4.2，结构回退／生产备份恢复仍需明确授权和验证。草稿首次在合成库发现CHECK格式差异，修正声明而未放宽比较器，失败现场保留；正式应用后不能改写该迁移。字段和检查见[字典](../technical/mysql8-table-dictionary.md#de-ent-audit-event)及[审计记录](organization-audit.md)。

## W03正式4.3—4.5迁移

[设计](w03-control-plane.md)新增4.3主体／成对任职／组织成员／管理资格六表、4.4凭据／平台资格／管理会话三表、4.5资源归属一表；当前目标15表164列，历史4.1—4.4描述冻结，不用最新目标代替历史校验。Hibernate仍不得自动维护企业表。每次DDL先验证全部历史结构及已存在新表，失败账本与已提交DDL保留后安全重试；不修复漂移、不回填默认身份或旧资源归属、不删除账本降级。

每版本描述必须可在独立类加载器中先加载；不得回调持有当前目标静态状态的外层工厂。生成列实测nullable=YES、默认NULL、STORED GENERATED，表达式逐字核对。测试覆盖空库、存量升级、部分DDL提交失败／重试、未知表视图／漂移／较新历史拒绝，失败历史保留。升级不自动提供默认授权或实际数据集绑定。跨行学校种类及主体角色范围由后续管理命令校验。

较新成功历史对旧包默认拒绝；回退需兼容该历史的包或明确授权的备份恢复，本步骤不删除数据或历史来降级。未来APP分支、列范围等另加版本，不改写已执行4.7。
