# 数据库迁移规范

源码现状：`InitSqlListener` 在启动时收集 `SqlBlock` Bean，按版本组 1、2、3 执行，并把版本、成功状态写入 `de_standalone_version`。失败记录保持 `success=false`，下次启动会尝试重跑同一版本。`spring.flyway.enabled=false`，部分 Profile 使用 Hibernate `ddl-auto:update`。

首期采用现有 `SqlBlock`，不叠加 Flyway/Liquibase。企业扩展迁移版本组需在 POC 中确认加入执行顺序；未通过该验证前禁止向生产库运行企业迁移。

每个迁移必须包含：唯一版本号、表/字段变更、历史数据回填、前后置条件、失败重试处理、验证查询和回滚/恢复说明。禁止修改已经执行的版本；失败重试不得重复插入、重复删除或产生重复索引。

租户化采用“扩展 → 回填 → 校验 → 收紧”四步：先加可空字段和新索引；建立默认租户并回填可判定资源；核验所有行、引用关系和计数；最后加非空约束及唯一约束。每一步在隔离数据库上以空库、存量库、失败重启三种场景验证。对不能判定归属的行暂停，不猜测租户。

生产执行前创建元数据库和文件存储一致性备份；应用版本与迁移版本绑定。若新结构无法向后兼容，先实施双读/双写或维护窗口；回滚须采用经过验证的备份恢复，不假设反向 SQL 安全。
