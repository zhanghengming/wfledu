# 登录回归与交付门禁

2026-10-07，W02/T01测试入口补强。业务范围及A/V编号不变；本文件定义当前社区兼容验收的实际入口，不代替未实现的集团权限或宿主嵌入验收。背景见[404根因](../planning/w02-login-404.md)，逐功能流程见[远程开发规范](remote-workflow.md)。

## 为什么此前没测出来

原4项检查通过HTTP读取主页、公钥和加密登录接口，直接调用服务端登录，绕过了浏览器的认证配置初始化、加载遮罩、移动端表单校验及路由跳转。主页200、密码正确和构建成功都不足以证明页面能登录。测试方案把端到端主要放在首期发布前，缺少每次整包的桌面/移动共同基线；临时浏览器驱动没有进入正式工具目录。

本次修复过程中桌面通过后移动仍失败，是入口覆盖不足的实证。上一次的API结果保持真实有效，但其证明范围仅限接口；当时据此认定页面可验收，判断超出了证据范围。

## 每次整包必须执行的8项浏览器检查

| 入口 | 用例 | 必须观察的结果 |
| --- | --- | --- |
| 桌面、移动各一项 | 冷启动初始化 | 新浏览器上下文、无登录缓存、禁用Service Worker；控件可用且加载遮罩消失；实际HTML/启动JS/CSS与JAR内SHA一致 |
| 桌面、移动各一项 | 错误密码 | 实际点击表单并发出POST；服务端40001拒绝，不返回Token，仍在登录页 |
| 桌面、移动各一项 | 正确密码 | 实际点击表单并发出POST；成功返回Token并进入各自工作台；包含服务端可接受而旧移动复杂度规则拒绝的专用社区凭据 |
| 桌面、移动各一项 | 登录后刷新 | 保持已登录路由；页面、API及静态资源无新增失败 |

全部API的HTTP错误、未捕获页面JS异常、XHR/fetch/script网络失败及静态资源错误都失败；明确社区模式下请求两个缺失扩展配置接口也失败。仅已记录的`/favicon.ico`静态404允许，不豁免任何API404。浏览器抓取只记录路径、状态及固定错误代码，不保存请求体、Token、密码、localStorage、HAR或trace。

每次分别新建桌面和移动上下文，不继承管理员已登录状态。移动入口直接打开mobile.html，避免只依赖桌面组件覆盖。只有8项齐全且通过才产生合格浏览器结果，缺移动用例或有未执行项均不通过。

## 证明测试能发现故障

| 故障控制 | 浏览器内的注入方式 | 必须捕获的失败 |
| --- | --- | --- |
| unexpected-404 | 拦截当前必需的sysParameter/ui并返回404 | API_HTTP_ERROR |
| loading-mask | 给登录页面增加一直可见的加载遮罩 | LOADING_MASK_VISIBLE |
| mobile-submit-blocked | 阻止移动登录按钮发出实际提交，模拟客户端校验阻塞 | LOGIN_REQUEST_NOT_SENT |

注入只发生在测试创建的浏览器上下文，不改动服务器、源码或数据库；每个故障报告都必须失败且命中指定原因。故障报告不能作为正常回归成功结果。真实故障可能有不同触发方式，本控制证明当前检测点有效，不宣称覆盖全部可能缺陷。

[报告拒绝测试](../../tools/phase1/test-delivery-gate.py)现为17项：保留正常结果接受及缺移动、登录失败、API404、过期、旧提交/产物、零单测、用故障报告冒充成功、缺故障控制、新运行/失败状态、缺foundation的检查，并增加“数量足够但缺必需用例”、旧39项回执及缺命名回归证据的拒绝；本轮再增加缺JPA用例、缺JPA回执及旧46项回执的拒绝。

## 可重复执行的入口

2026-10-08门禁版本更新见[校验整改记录](schema-validation-review.md)：当前必需Java至少60项（装配12、上下文10、配置6、迁移18、JPA隔离14）和回执17项；八个校验回归及14个JPA隔离名称必须出现在实际XML及回执中。旧39/11项、第一轮45项及上一轮46/14项只属于历史记录，不能作为当前交付门槛。桌面/移动8项及3个故障控制保持不变。

在本地PowerShell 7执行，使用已经安装的Chrome、Node和Playwright模块；服务器保持专用18100运行，现有SSH18010转发到该端口。模块路径由当前工具缓存或受控工具安装提供，不把临时npx缓存目录写死在工具中，也不自动安装浏览器、依赖或改变服务。

```powershell
./tools/phase1/verify-delivery.ps1 -PlaywrightModulePath '<已存在的Playwright模块绝对路径>'
```

[统一门禁](../../tools/phase1/verify-delivery.ps1)先验证目标SSH转发、任务进程所有者/命令及独立配置，再在远程执行真实60项单测、核对8个结构及14个JPA必需命名回归、5项HMAC、4项API、14项业务数据库、10项基础元数据、17项报告拒绝测试和三项完整包拒绝启动（含基础迁移开关错拼）。然后执行8项真实浏览器用例及3项故障控制。当前脚本默认仅支持这套已授权W02社区测试区，不能直接指向其他部署或未实现的企业运行模式。

凭据只读取专用管理员字段，通过SSH和进程stdin传递，不输出、不写文件、不改剪贴板。不能把整个含数据库密码的私有配置回传到本地。当前网页包和产品源码没有变化时无需因测试工具更新重复打包；产品改动仍先按规范整体构建、运行对应包，再执行本门禁。脚本不会替你构建、部署或重启服务。

## 证据一致性与推送限制

- 对比测试前后提交、全部受跟踪Core/SDK产品源码摘要、测试工具摘要、JAR SHA、PID和进程启动标识；生成的auto-imports及静态产物排除在产品源码摘要外。产品文件修改时间晚于JAR或JAR晚于进程启动时拒绝，避免新源码配旧包或旧进程配新磁盘文件。
- 浏览器实际加载的HTML/启动JS/CSS逐项核对JAR内摘要，覆盖当前静态文件名没有内容hash时的旧页面问题。
- 单测报告必须由本次命令新生成，覆盖五个必需测试类、数量不低于60（装配12、上下文10、配置6、迁移18、JPA隔离14），失败/错误/跳过为零。八个必需命名回归按[执行工具的SCHEMA_REGRESSIONS](../../tools/phase1/login-test-context.py)及14个JPA名称JPA_REGRESSIONS逐项核对XML及回执，不能用无关用例凑数。其他检查结果复制到唯一runId目录，不覆盖原交付历史。
- 交付结果使用服务器时间计算一小时有效期；客户端时间仅记录浏览器运行，不用于服务端有效期判定。每次新运行先将旧回执置为不通过，只有全部成功才替换；检测到过期、提交/源码/工具/运行包变化、缺项或失败时退出非零，不沿用同一HEAD的旧成功报告。此专用测试区一次执行一个门禁，不同时发起多轮。
- 当前远程任务仓库安装[pre-push检查](../../tools/phase1/pre-push-check.sh)：仅对自有codex/phase1-*分支的Core/SDK/测试工具改动要求当前HEAD有合格门禁回执。纯文档推送检查差异，不要求浏览器。不能覆盖他人的已有钩子，也不修改全局Git配置。

该钩子是当前开发检出的保护，不是GitHub分支保护或全团队CI；其他检出须按本流程安装，合并仍按人工评审执行。人为绕过本地钩子不能保证被远端拒绝，后续接入组织CI后再增加服务端必需检查。本轮不安装CI服务或公开测试端口。

## 扩展原则和本轮状态

每次发现遗漏先增加能捕获该问题的场景，修复后重跑正常与拒绝路径；不能仅增加首页200检查或扩大错误豁免。W03身份、W05查询、W06编辑、W07嵌入和W09导出实现时，把相应桌面/移动/panel/iframe入口按影响加入必测清单；业务A/V沿原验收记录，不提前写通过。

本轮工具、故障控制及实际结果追加在[W02记录](../planning/w02-security-baseline.md#10-登录测试门禁补强)。本文件是规则和工具说明；完成状态以有runId、提交及远程结果的记录为准。无需也无法承诺软件永不出现Bug，但相同的API404、遮罩阻塞和没有真实登录请求不能再通过本门禁。

W03扩展见[基础迁移设计](foundation-migration.md)；缺foundation的旧W02回执不能放行，参与执行的全部工具纳入指纹。集团权限业务A/P仍待实施。
