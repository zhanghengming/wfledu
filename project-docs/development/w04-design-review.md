W04可以在W03真实身份／管理事务／主体／任职存储上增量实现，不需要迁移React、不引入另一套ORM、不把管理资格改成学校数据权限。DDD采用纯授权规则＋可信事实加载＋短事务编排；不为领域分层全面移动既有实体或拆微服务。

## 3. 需要由后续实施解决的工程门槛

1. 角色／任职及旧成员／组织入口的影响集合、锁序和资格比较需在实际事务中证明；本轮仅定义约束，不将潜在风险写成已复现产品Bug。
2. 4.6／4.7编号、DDL、生成列元数据及JPA只读映射在隔离探针通过后冻结；现有15表与账本保持。
3. 新SDK字段／路由与局部解析器／集团作用域同时接入，不能先将接口加入公共白名单再补鉴权。
4. 决策来源和分页需有明确大小限制；权限计算不因截断“禁止”来源而放行，分页只用于展示。
5. 外部查询、缓存、任务及下载交付的并发撤权在后续包验证；本轮无该能力实证。管理资格现有更保守的学校有效性规则不被业务计算默默替换。

这些是第1步提出的后续工程项，不需要用户选择ORM、事务管理器或算法。真实宿主／公司指标不是W04开始条件。第1步未执行安装、构建、数据库命令、应用重启、Git发布或商业版私有实现调查；第2步实际进展在下节。

## W04第2步编码后的架构与优化复核

第2步已按实际调用链落实[角色任职及守卫](w04-role-assignment.md)。先在旧整包复现委托成员管理员加入授权组织时被错误放行，再修复。开发者复核确认：SDK单向依赖；Server严格边界；集团事务中先鉴权、后CAS／集合替换、资格复查及最后管理员检查、最后审计；新路由不绕过旧认证关闭条件。

补齐组织子树影响集合、角色任职受影响用户及当前有效七能力比较；变更后flush／clear避免读取旧EM缓存，资格变化须变更前MANAGE_AUTHORIZATION，不依赖角色名称。不把目标用户绑定到操作者ThreadLocal。沿原组织事务内核的校验／审计回调执行，守卫失败整事务回滚。

根因是原测试只证明单项管理权限，没有覆盖“管理组织关系／任职→改变有效管理资格”的组合。优化落实为同一个变化守卫、真实HTTP失败前后状态断言、四个具名方法＋48个关键接口集合、旧版本失败证据、交付门禁和交付后自动重走流程。新接口实际隔离的双向写入与三类筛选逐一验证，不能用计数代替。

性能限制单列：组织拓扑查询及每用户七能力重新求值随规模增长，本轮未做生产容量测量。下一优化先增加同版本批量事实与查询数量证据，再在保留全部拒绝回归下减少查询；不为形式上的DDD拆更多模块或提前缓存。此项不阻断单节点合成验收，但不能宣称生产性能已通过。集团业务表／SQL、规则批量与幂等仍按后续W04/W05执行，不提前关闭工作包。

用户／团队独立评审待记录；本节为开发者架构复核。最终整包、门禁及交付后验收结果追加在单元记录，不能由这份源码复核推断测试通过。

交付检查新增两端文档摘要和U+FFFD检查：本轮远程五份W04文档曾因Windows CP936终端输出被UTF-8解码而乱码，链接／围栏检查不能发现文字语义损坏。修复使用ASCII转义JSON或原始字节传输，不复用损坏副本；先保护目标旧摘要，再逐文件核对。产品未变，文档修复单独提交，最终HEAD仍自动重走验收。


## W04第3步开发者架构复核

存储与管理资格分开，主体／资源／学校通过复合键保持集团归属；生成槽是唯一约束实现细节，不是可使用资源或最终授权。JPA生成列只读，身份自然键不可替换。4.6普通规则默认DISABLED；4.7仅USER，不引用尚未存在APP表；不因建表创建权限、资源绑定或页面。服务层跨行规则／幂等重放鉴权仍待第4步证明。

已复现并修复冷加载初始化循环：V46构造时调用外层静态工厂，外层当前目标又依赖尚未完成V46。旧测试热加载顺序掩盖缺陷。新独立类加载器覆盖每版本先加载，旧包失败、新包成功，历史DDL一致；旧成功回执归档失效。优化落为“不回调当前目标静态状态的描述构造＋每版本冷加载＋旧包失败证明＋必需名称门禁”，非单纯增加测试计数。

编码前真实MySQL探针发现锚定正则允许末尾换行，4.7使用非白名单字符拒绝式并验证三类控制字符；多字节JSON按字节而非字符限制。幂等摘要防御性复制／32字节校验、唯一键并发、真实Spring事务下结果／规则／epoch／审计回滚纳入测试。每个小功能整包，最终交付后新runId独立重走流程，范围与证据见[存储记录](w04-authorization-storage.md)。

本轮为开发者架构复核；独立人工评审仍由用户／团队记录。未实现授权批量命令、事实求值、生产规模负载、实际业务SQL、编辑／嵌入／导出任务，不将存储夹具证明扩大到这些入口。下一步使用已测试的持久化契约，不提前缓存权限或引入第二套ORM。


## 4.7恢复及验收协议的架构优化复核

资源故障说明“单次编译成功”不是可持续构建的证据。资源执行器统一承载Maven／Node／测试，固定cgroup内存及CPU／进程上限、任务互斥、可用量门槛、低余量中止、超时及孙进程清理；实际主机余量、内核峰值、OOM与退出码共同留证。前端8GiB组／7GiB堆／10GiB启动门槛来自失败后人工容量复核，不自动扩容。3GiB／5GiB堆失败和受限成功都保留。低并发Vite继承原构建插件及全部产物，不改变产品功能来掩盖资源缺口。

暂时不用的任务应用停止后恢复；专用MySQL进程缓存释放用原参数清洁重启，前后UUID、配置、库清单和四库数据摘要相等。实际buffer_pool为256MiB，约3.6GiB RSS不能直接解释为缓冲池大小。该操作是本轮经身份核对的串行恢复，不是自动内存清理策略；后续数据库维护必须持有同一个作业互斥租约并新核对进程身份、备份与数据摘要，不自动重启数据库或旧服务。

机器回执失败来自库函数stdout与JSON协议混用。优化落实为库无摘要输出、CLI单对象响应、完整JSON严格解析、六类协议探针、回执形状与工具摘要的服务端拒绝。完整门禁能检出本轮污染，仍应在接口级测试提前覆盖；Python60项拒绝测试与PowerShell6项真实协议测试同时成为必需门禁，不降低远程／本地回执相等检查。重任务锁为每个作业持有；跨多阶段流程还依赖运行身份前后比较，应避免并发交付流程相互使回执失效。

当前完整包及运行测试结果见[存储记录](w04-authorization-storage.md)。交付后另以新runId执行用户流程，完成后在[独立验收回执](../../output/w04/w04-step3-post-delivery.md)记录最后复核。未完成的业务命令和幂等重放、生产规模、业务取数／编辑／嵌入／导出继续按后续工作包实现。此为开发者架构复核，独立人工评审仍由用户／团队完成。

## W04第4步开发者实现复核（2026-10-09）

复核[命令设计与源码接点](w04-authorization-commands.md)：SDK单向，Server仅边界编排；固定嵌套语法、精确路由和集团上下文同时装配。企业模式的异常脱敏Advice需覆盖新增服务器包；首次真实DB失败测试发现遗漏并修复，不把通用异常拦截器的拒绝码当作本接口的错误契约。新用例要求40001且无SQL泄漏。

真实两工作线程发现集团锁前已被认证recheck加载：find加锁不能假定重载对象，旧版本导致并发内部失败。共享事务加锁refresh再检查epoch，既有用户／会话／集团锁序保留；一方提交一次，另一方可因旧上下文拒绝，之后重试当前鉴权得到原结果。新增并发HTTP用例进必需方法，不依赖单工作线程的串行“并发”。

另外两项首轮失败来自夹具：JDBC JSON byte[]的对象地址不能作为状态比较；已用CAST AS CHAR比真实内容。学校SCHOOL的school_id应null、過期必须保留expires_at>created_at；样本按冻结约束构造，未放宽生产DDL。严格UTF8校验阻止JSON自动探测其他编码绕过声明。三类主体写和缺ORG主体一起回滚，读不制造状态。

事务先完整验证变更、先删除flush再创建，同批CAS、学校集合、epoch、审计和幂等结果；最后管理员检查在flush/clear之后看新状态。只保存安全结果元数据，不以成功配置放行数据。保留当前集团锁来串行化管理写，读与写均禁止缺上下文。授权的业务求值与实际数据出口还未实现，不提前使用缓存。

性能与容量仍单列：学校／祖先批量读取≤500一批／最多128层；回读学校页有上限。规则页当前每行分别读取学校首段和总数，≤100行有界，但生产容量和查询次数未测；下一步同版本事实加载应建立查询次数证据再合并查询。没有基准前不引入缓存或额外服务。最终整包和交付后复验的结论应在全部流程完成后补充，本文不是独立人工评审。
