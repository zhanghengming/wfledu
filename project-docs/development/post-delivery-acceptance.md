# 交付后自动验收规范

2026-10-08，用户明确要求：本次按W03最终交付回执实际测验；以后每次交付后，代理自动执行自己提供的验收流程，无需用户再次触发或逐步确认。本规范补充[远程开发流程](remote-workflow.md)和[测试规范](testing.md)，不改变PRD或原环境保护边界。

## 固定执行顺序

1. 读取本次最终回执、工作包及验收手册，把回执中的流程、命令、必需用例、预期结果和未覆盖项列成执行清单。后续新增功能使用对应最新清单，不永久固定为W03数量。
2. 核对交付源码和运行包：实际HEAD／任务分支、源码与工具摘要、JAR摘要、进程／开始时间、配置摘要、专用端口及数据库；记录已有修改，不覆盖两端原有内容。产品代码或包发生变化，先依规范重新整包构建、运行再验收。
3. 实现与Git交付完成后、宣布本次最终验收通过前，主动重走回执中提供给用户的流程。独立执行用户复现命令，再执行本次完整门禁；不能只读取上一轮成功报告或只核对首页200。
4. 对实际开放的接口／页面执行正常流程、越权拒绝、撤权、边界及故障检出；人工页面操作由已有浏览器自动化复现。没有可执行入口或需要外部材料的项目明确记录待验证，不能用单测或合成宿主代替真实接入。
5. 失败即保留日志和失败状态，分析、修复并重测；行为代码改变后重新远程整包验证和最终提交绑定。失败、缺项、过期或源码／工具／JAR／进程变更后的回执不能宣称通过。
6. 生成独立Markdown验收记录，填写交付对象、实际执行命令／退出码、必需名称及数量、正常与拒绝结果、runId、报告位置、未覆盖项和原修改保护结果。当前机器回执会更新，之前的报告按runId归档保留。
7. 最终回复报告本次真实结果与记录入口，同时更新相关工作包的当前结果引用。此流程在每次交付中自动执行，用户不需要另发“开始验收”。

纯文档交付按回执中的文档静态、链接、示例及差异流程验收，不为文档更改额外构建或启动应用。本次用户明确要求W03完整功能复验，仍运行W03全部实际接口和完整门禁。Git同步不是生产发布；本规范不授权改动旧业务库／目录／服务、读取秘密到聊天、安装未知依赖或部署生产。
