# 日志、指标与审计规范

每个请求生成或接受受信任网关传入的 Trace ID。应用日志结构化记录时间、环境、版本、Trace ID、租户 ID、主体 ID、App ID、接口/资源、耗时与错误码；不记录 Token、Secret、密码、完整 SQL 参数和敏感结果。异步任务沿用同一 Trace ID，新增任务 ID。

审计事件与运行日志分离。登录、租户切换、授权变更、管理员代理、数据源凭据变更、嵌入换票、导出与下载必须记录成功和拒绝结果。审计事件至少含租户、操作者、目标、动作、时间、来源和结果；普通租户管理员不能修改或删除。高风险操作若审计写入失败的处理策略需在安全评审中明确。

指标首期覆盖 API 错误率/延迟、JVM、数据库连接池、Redis、查询耗时与并发、导出队列长度、Ticket 拒绝/重放、登录失败、按租户用量。指标标签禁止使用用户 ID、看板 ID 等高基数标识；按租户聚合的指标需要控制租户数量和监控成本。

告警阈值在压测后确定。生产排障先用 Trace ID 定位，再以租户和任务 ID 关联日志与审计；任何调试开关必须有过期时间和审计记录。
