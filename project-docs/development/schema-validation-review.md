## 待闭环的缺陷

1. 字符串默认值统一转小写，使 `DISABLED` 与 `disabled` 被错误视为等价。
2. 索引只检查聚合列名，遗漏 `SUB_PART`，完整唯一索引和前缀唯一索引被错误视为等价。

2026-10-08只读评审已确认任务库当前默认值和索引正确；这不是已观察到的业务数据损坏。本次修复前，上轮“本范围无新阻断项”的自评结论暂停采用。

## 设计及测试方案

- 字符串仅去掉 SQL 外层引号并还原双单引号转义，保留大小写、内部引号和空白；只有明确支持的 CURRENT_TIMESTAMP(precision) 函数允许函数名大小写差异。NULL 与字符串不混同。
- 索引按键名和顺序读取每个字段，核对完整字段数量、唯一性、列名、顺序、无前缀、升序、BTREE 和可见性；不使用可能丢失 NULL 项的列名聚合作为唯一证明。
- 新增真实 MySQL 漂移测试同时覆盖补建前拒绝和已成功迁移后的启动拒绝；先确认偏差实际写入，再断言目标校验拒绝，保留偏差现场、不自动修复。
- 所有新增 Java 测试进入正式门禁的必需报告和最低数量；更新工具指纹。不以旧回执或新增测试文件存在作为通过证据。

## 为什么设计和编码仍然漏掉

| 环节 | 本次具体原因 | 已落实或后续门槛 |
| --- | --- | --- |
| 设计 | “检查default/全部索引”只列对象，没有定义每个属性的等价边界 | ADR-015列精确比较、允许适配、未知形式的处理及对应拒绝证据 |
| 默认值实现 | 把SQL标识符/函数名大小写习惯扩大到字符串数据；CHECK保留字面量的规则没有覆盖另一条默认值比较路径 | defaultMatches仅对已知时间函数容忍大小写；字符串保留内部引号和空白，NULL单独处理 |
| 索引实现 | 用GROUP_CONCAT得到相同列名就认为索引相同，遗漏SUB_PART；同方法还会丢失NULL函数字段，未比较排序方向 | 按索引及SEQ_IN_INDEX逐项检查项数、列名、前缀、方向等元信息；覆盖额外函数字段和降序拒绝 |
| 测试 | DDL生成与校验依赖同一声明，正常通过存在同源盲区；已测试长度/CHECK漂移，却未测试近似结构 | 四个新用例先在旧校验上全部失败，随后真实MySQL变异验证；新测试进入必需名称而非只增加总数量 |
| 评审 | 自评主要确认分层、失败重试和已有测试通过，没有沿每个信息变换检查丢失属性；独立评审尚未进行却提前写“无新阻断项” | 修正交付结论；之后设计/编码评审逐属性核对规范化、聚合、默认和未知分支，独立人工结果另记 |

这不是需求不明确或MySQL随机行为：原设计要求精确默认值和索引，本次实现与证据不足。39项通过只能证明原有用例覆盖的行为，不能证明校验语义完整。通过设计属性表、先失败后修复、独立变异证据和门禁拒绝缺用例降低同类风险，不承诺以后不会出现任何bug。
