# ADR-015：精确结构校验、迁移版本与启动就绪

2026-10-08。状态：本轮采用结构校验及测试整改；JPA 自动 DDL 隔离已在本轮W03单元实现与整合验证，详见末尾更新；版本演进和企业请求就绪控制仍待实施。用户要求修复校验遗留并优化后续架构；不变更 PRD v1.2、R/A/V/P 编号或首期边界。

## 问题与替代范围

W03 的设计要求默认值和索引结构一致，实际比较却将字符串转小写、将索引字段聚合为列名。正常建表和少数漂移测试不能证明这些信息没有丢失。本决策补充 ADR-008 的迁移验证和 ADR-012 的基础设施一致性要求；保留既有 SqlBlock、单节点及集团分库决定，不引入新 ORM 或迁移框架。

## 本轮采用的实现契约

| 比较对象 | 必须保留的语义 | 允许的适配 |
| --- | --- | --- |
| 字符串默认值 | 大小写、空白、内部引号、NULL 与字符串的区别 | 去除 SQL 外层引号，解码双单引号；不使用全局 lower/trim/去引号 |
| 时间默认值 | 函数种类及精度 | 仅已支持 CURRENT_TIMESTAMP(0–6) 的函数名大小写 |
| 数值默认值 | 现有整数默认值精确一致 | 本轮不增加任意数值或表达式等价规则 |
| 索引字段 | 键名、每项顺序、项数、唯一性、列名、无前缀、升序、BTREE、可见性 | 逐项读取 STATISTICS；不以 GROUP_CONCAT 列名取代完整字段核验 |
| CHECK | 强制执行、字面量及 AND/OR 分组；字符串内的字符集前缀文字和反引号不能删除 | 字符集引入符/标识符反引号只在字符串外处理；仅现有受控表达式的 MySQL 展示差异，不作为任意 SQL 等价解析器 |

MySQL COLUMN_DEFAULT 对显式 DEFAULT NULL 和未声明默认均返回 NULL，本契约只声明它们的默认值语义一致，不宣称可以还原原始 DDL 文本。后续表达式、生成列、函数索引、前缀或降序索引必须先扩展声明、元信息比较和独立漂移测试，不能悄悄放宽比较。

元信息依据：[COLUMNS](https://dev.mysql.com/doc/refman/8.0/en/information-schema-columns-table.html)、[STATISTICS](https://dev.mysql.com/doc/refman/8.0/en/information-schema-statistics-table.html)。本轮补建前检查和成功版本后的只读检查使用同一修复后的规则；失败不自动 ALTER/DROP，不猜测结构修复。

## 后续 W03 必须落实的架构

1. **历史版本与当前目标分离。** 4.1 建表声明冻结；4.2 使用新增 SqlBlock 及独立目标结构，不修改 4.1 的 DDL。历史迁移负责版本转换，当前结构验证负责最新完整目标。升级已存在新版时不得用旧版严格结构检查误判为漂移；执行顺序和失败重试在新增版本前验证。
2. **正式迁移与 JPA 映射分离。** 在新增企业实体前，通过 POC 确定不让 Hibernate 自动 DDL 接管企业表的机制，仍保留社区表兼容。结构成功后映射正式表；不能让自动 update 先修改结构再由验证器接受。具体过滤/启动机制尚待源码调查，未证实前不注册企业实体。
3. **监听端口与业务就绪分离。** 企业启动状态在迁移、当前结构验证和受控初始化全部成功后才就绪；失败持续拒绝企业业务请求。就绪探针与后端实际入口都检查，不能只靠网关或隐藏按钮。初始化命令使用独立受控入口，不开放浏览器自助提权；现有社区行为保持兼容。
4. **校验者与证据分离。** 同一声明生成 DDL 和比较规则可以减少重复，但测试必须用字典明确的预期及实际 MySQL 变异证明边界。为新增安全契约列出精确比较属性、允许等价属性、未知/缺失处理、允许/拒绝/边界用例与所有执行入口。

目前 FoundationSchemaVerifier 是 ApplicationRunner，端口可能在其完成前监听。本轮未开放企业 HTTP 服务，未实现上述请求就绪控制；后续工作包必须验证迁移阻塞期间、失败期间和成功后的真实直接 HTTP 请求，不能将进程存活或首页 200 当作就绪证明。

## 测试和评审门槛

- 新增校验用例先在旧实现中暴露遗漏，再在修复后通过；测试失败原因必须是目标校验未拒绝，不是环境连接或夹具构造失败。
- 每个用例先确认结构变异实际存在，再检查拒绝，最后确认校验未自动修改偏差或业务数据；新增合成库保留现场。
- 门禁检查真实 XML 的失败/错误/跳过、测试项数和必需用例名称；回执还要记录本轮必需用例，旧 39 项回执不能放行本次修复。
- 收尾逐属性复查发现CHECK全局删除字符的同类遗漏，追加真实MySQL先失败证据后修复；最终最低46项Java及8个命名回归，第一轮45项通过不作为最终放行依据。
- 安全设计评审逐属性检查信息是否被规范化、聚合、缓存或序列化丢失。测试数量和同源自评都不是独立证明。
- 独立评审由用户或团队记录；开发者自评不代替另一位评审者，不以本决策自行合入或开放企业服务。
