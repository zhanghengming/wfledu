# W08基础管理页面的实施设计

2026-10-09。依据[连续清单](../planning/w05-w10-continuous.md)、[PRD页面要求](../requirements/prd.md#6-页面与交互要求)、[前端与编辑](frontend-editor.md)及W03/W04实际SDK契约。本轮先闭环“管理员从页面登录、选择自己可进入的集团、建立学校/成员/配对任职”；矩阵、源、模板、嵌入页面随成熟接口补齐。本设计不是实现或验收通过记录。

## 当前公共源码接点

- `ManagementRequestFilter`目前只接受企业管理API，拒绝其他路径；旧社区静态页及认证/数据出口保持关闭，不能让管理页加载触发这些接口。
- `IdentityManagementApi`提供登录、改密、退出、当前上下文和CAS切换。`tenants/page`是平台发现，不是普通成员集团列表；不能复用于普通集团管理员发现。
- W03/W04的组织/成员/角色/任职API已验证，Long ID和版本是字符串，管理能力独立于业务权限。复用同一管理事务和求值，不按角色名称决定菜单。
- 前端`config/pagesConfig.ts`扫描`src/pages`；独立页面需HTML入口。现有Axios在模块初始化请求超时配置，随后使用社区Token刷新/HMAC；该流程不能用于已关闭旧URL的企业管理模式。

## 页面及客户端边界

新增Vue多页面`enterprise.html`及独立管理路由/布局，沿用现有Pinia、Element Plus、国际化和Axios服务。入口不运行社区`permission.ts`初始化，不访问XPack配置、社区外观/登录/默认菜单接口。共享Axios增加明确企业命名空间分支，保留社区和已有嵌入行为；组件不另建Axios实例。

企业分支只发往当前页面同源的配置API前缀，仅发送实际企业Bearer凭据和语言，不附加社区/分享/嵌入Token或HMAC，不执行社区刷新。成功只接受code=0；包括旧社区特殊code=50002在内的冲突必须拒绝，401清理凭据与页面状态，403/冲突保留明确提示而不伪装为空数据。异步响应核对本轮页面身份和上下文，切换后旧响应不得重新填充列表/草稿。

管理会话独立于社区存储键。令牌不得写URL、日志、截图或测试报告；刷新后先重查当前服务端上下文，不能仅凭浏览器缓存展示旧集团。登出和强制改密清除本地状态。页面按服务端当前管理能力显示入口，后台各原API继续独立鉴权。

受保护菜单和业务子页面的渲染前提必须同时包含凭据存在、服务端principal存在、不处于强制改密及不处于集团切换。`clear()`改变generation后可能先于异步路由跳转触发重新挂载，不能只依赖跳转登录保证销毁；清空认证状态即关闭业务渲染，禁止退出/失效期间从重建组件发出无凭据请求。

管理入口在同源CSP下运行，不允许eval。当前纯文本消息直接使用可信消息函数；后续插值/复数消息使用构建预编译，必须在打包入口及实际安全响应头下验证。页面异常、被框架捕获的Error和script/connect CSP违规都纳入浏览器门槛，静态资源200不能替代初始化渲染。

分页与列表请求共用busy状态；加载期间禁用所有分页控件，避免页码已变但新请求被忙碌保护跳过。切换、刷新、退出及验收脚本必须观察实际路由、请求/表单就绪；多页数据按真实分页查找，不能假定新集团均在最后一页。组织、成员及角色/任职遵守相同规则。

页面依次覆盖登录/必要改密、集团选择、组织/学校、成员、角色/任职。字段使用明确表单、已授权对象选择器及版本；不以JSON编辑器或角色名称特判代替配置页面。集团管理员添加已有全局用户沿现行ID契约，平台创建用户只展示一次临时凭据输入，不开放全局用户列表给集团管理员。任职以一成员＋一角色＋所选学校完整保存，停用可清空；不把学校集合与角色集合交叉组合。

## 必要后端契约补齐

新增`context/tenants`分页：当前有效身份重新核验；普通用户只列其有效成员关系的有效集团，平台专属资格可发现有效集团。使用参数化查询，不先返回全部集团由前端隐藏。

新增`context/navigation`：返回当前身份/会话版本、当前集团及accessEpoch、平台能力和当前集团管理能力；本集团能力复用`ManagementAuthority`实际算法，读取事实时与现有会话/集团锁协调，不在前端构造最终资格。没有选集团时不返回其他集团管理能力，平台全读不产生编辑/管理能力。

页面在集团操作请求中发送成对的`X-DE-Context-Tenant`和`X-DE-Context-Version`；服务端核对各唯一、合法且与认证会话当前集团/版本相等。旧脚本未提供该对字段时保持既有兼容，提供一个、重复、伪造或不匹配均拒绝。现有管理事务再次锁定并核验会话，处理认证后并发切换；这对字段是防旧页面误投的前置条件，不是授权来源。

企业管理进程仅开放GET/HEAD的管理HTML与受控构建静态资源，拒绝路径逃逸、编码歧义、错误方法、私有文件及旧业务URL。静态资源由类路径`static`读取；不开放文件系统路径或任意下载接口。就绪前仍拒绝。运行时仅为本任务测试进程配置确切本机管理Origin；原Origin及私有参数保留，生产来源通过既有配置受控指定。

## 内部步骤与测试门槛

1. 导航发现、上下文前置条件和静态资源边界：真实MySQL/Servlet验证普通集团范围、平台逐集团资格、无成员/停用/撤权、错误头及事务不写入；静态路径不能转入旧业务。
2. 共享Axios企业分支和Pinia会话/路由：定向lint/类型检查，状态与异步负例，不串社区Token或第三方baseURL，冲突不吞掉。
3. 登录/改密与集团切换页面：实际浏览器冷启动、错误密码、成功、刷新、过期/退出及切换清理；无不预期API错误/加载遮罩/JS异常。
4. 组织、成员、角色/任职逐页：实际表单建立→保存→重读，保留ID精度、显式清空、CAS及停用；多校任职配对、两方向跨集团、无管理资格拒绝和切换中的迟到响应。
5. 功能完成后远程整包，运行相关实际页面及接口、原社区桌面/移动入口；阶段结束累计门禁纳入具名W08用例。正式交付后另走页面用户流程与新完整门禁，保存绑定证据。
