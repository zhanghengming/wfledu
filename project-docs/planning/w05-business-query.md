## 业务闭环和边界

集团管理员在本集团登记受控数据源，核验它只连接本集团数据库并使用只读账号；把原生业务数据集及其学校字段、完整依赖绑定到已验证数据源。用户依据当前学校、数据集及操作授权查询，财务数据集与其他业务数据集分别决策。同一用户的学校和角色不做交叉组合。平台读取资格逐集团生效，不能绕过源归属、未知学校拒绝或自动取得编辑/导出能力。

先使用现有专用MySQL 13306及两套合成业务库验证，不借用原3306或真实业务库，不自动创建新实例。新增元数据迁移仅运行于隔离测试元库；DDL执行前登记当前版本、目标表和恢复方式。不把原生数据源ID、客户端数据库名或SQL限定名当作可信集团归属。

## 必须证明的允许、拒绝和边界

| 类别 | 必须记录的真实结果 |
| --- | --- |
| 允许 | A校校长：A校已授权全部业务数据集；B校财务：仅B校财务数据集；学校编号以可信组织映射形成参数 |
| 双集团拒绝 | A身份使用B数据源/表/字段/数据集/图表/绑定ID及反方向均拒绝；SQL显式限定B库和只读账号跨库访问实际拒绝 |
| 结构边界 | 学校字段NULL、空串、未知、停用学校和错集团映射排除；字段伪造、计算学校字段、漏依赖、未验证/失效配置不能执行 |
| 聚合 | 用人工可核算合成行证明SUM/COUNT、排序和分页只包含授权学校；不能查询后再删结果行 |
| 筛选/下钻 | 输入学校集合只能收窄范围；筛选选项不泄漏无权学校值；下钻仍在授权范围内 |
| 配置变化 | 绑定/数据集/字段/源配置修改使旧验证与连接/缓存不可继续使用；请求执行和结果交付均核对当前状态 |
| 撤权竞态 | 使用真实请求阻塞点撤权，再放行结果；旧结果不交付。分别覆盖缓存命中、查询执行、错误处理和下一请求，不能只测新登录 |
| 错误/日志 | 响应及报告不包含SQL、密码、参数值或连接详情；原Provider参数日志路径需核对，不能直接复用后声称已脱敏 |

## 已确认的源码事实与尚待证明的接点

原生实体位于`sdk/common/.../dao/auto/entity`。数据集表记录的数据源、类型及info与字段记录都必须从服务端读取并核对，不能仅信任页面提交的依赖列表。`DatasetSQLManage.getUnionSQLForEdit`返回SQL、dsMap、JOIN描述及`tableFieldWithValues`，SQL结构与绑定值须一起传递。

授权输出的`allowedSchoolIds`是元数据组织主键，业务表中的学校编号是受控`schoolCode`，两者不能直接等同。执行适配必须在当前集团、当前修订下核对有效SCHOOL组织并取得编号；编号的类型、大小写、字符集、尾空格比较和业务字段语义须实际验证。不能因为数据库默认大小写不敏感比较，把未登记的近似编号匹配为已授权学校；不兼容映射拒绝，禁止降级为无学校条件查询。

`ChartDataManage.calcData`在原生SQL构造后把SQLMeta交给图表Handler。`WhereTree2Str`的既有普通行权限合并包含OR，SQLMeta本身没有企业强制条件的参数集合；不能把学校条件作为另一个普通权限树直接加入。`CalciteProvider`有PreparedStatement能力，也有以数据源ID复用连接池及参数值日志的路径；现有能力是接点线索，尚不是集团隔离验证。

W04的PermissionDecisionService/FactLoader已经输出当前用户、集团修订、资源修订及学校允许减禁止，预览仍明确`executionReady=false`。只有源、学校字段、完整依赖和真实执行适配均通过后，才允许改变相应执行状态。原管理进程关闭的社区业务接口继续关闭，新入口逐项增加，不能批量开放旧入口来让页面工作。

最终支持结构、SDK字段、迁移编号及查询适配实现须在5.1实际证明后登记到对应技术与数据库文档；此工作包没有将候选接点描述为已经实现。
